## Clarifications

### Session 2026-11-14

- Q: 模型生成的摘要正文超过摘要字符上限时如何处理？ → A: 代码截断到上限后落盘（选项 B）。摘要要求中明确写出上限作软控制，截断仅为罕见兜底；编号信封由代码提取不受截断影响；不引入重试（重试策略维持范围外）。

## 用户场景与测试

### User Story 1: 长排查历史的 LLM 摘要式压缩（Priority: 高）

支持人员在多轮长排查中不丢失调查脉络：超过触发线的历史轮次被压缩为结构化排查摘要，关键事实与记录编号保留，调查可继续推进而非诚实降级。

- **Given** 会话原生消息流超过压缩触发线且压缩开启，**When** 下一次模型请求准备前，**Then** 切点之前的历史轮次被压缩为一条五段结构摘要（已排除假设/当前主假设/已确认事实/已知条件与约束/下一步排查项），摘要进入会话消息流，切点之后的最近完整轮次原样保留。
- **Given** 被压缩轮次的工具结果中出现过记录编号，**When** 压缩完成，**Then** 全部编号由代码从被删消息中确定性提取并写入摘要信封的结构化字段，不依赖模型转述的完整性。
- **Given** 同一会话发生第二次及以后的压缩，**When** 生成新摘要，**Then** 既有摘要正文作为既有进度传入合并要求，规则为「保留全部既有事实与已排除假设、新增进展、更新主假设与下一步」，编号原样保留；消息流内至多存在一条摘要。
- **Given** 摘要调用失败（网络异常、输出截断、空正文），**When** 本轮继续，**Then** 消息流原样不动、失败留痕、投影照常兜底，本轮调查不被阻断。
- **Given** 回答引用了仅存在于摘要中的历史编号，**When** 提交前核对，**Then** 不触发编造改写（编号可从摘要信封核查到）。

### User Story 2: 直连调用点的上下文护栏（Priority: 高）

multi-agent 的直连模型调用（路由/规划/合成/文档问答/闲聊）不再携带无界的拼接内容；用户原话永不截断。

- **Given** 直连节点的变量段（已知条件简报、调查报告集合、检索片段）超过单段预算且投影策略开启，**When** 该节点构造请求，**Then** 变量段被截断并携带显式截断标记（含被截断字符数与「可按记录编号重查」提示），用户问题原样保留。
- **Given** 投影策略未配置（默认），**When** 任意直连节点构造请求，**Then** 请求内容与现行为逐字一致（格式模板留在调用点，默认路径零改动）。
- **Given** 合成节点收到多份调查报告，**When** 构造请求，**Then** 每份报告先经读取端上限裁剪，单份超限带截断标记，多报告合成照常工作。

### User Story 3: 默认行为完全不变（Priority: 高）

全部治理能力缺省关闭——这是本特性可安全合入的前提（对齐 specs/002 US3 先例）。

- **Given** 未配置任何上下文治理键（默认），**When** 任意阶段处理任意会话，**Then** 模型请求内容与现行为完全一致。（003 例外注记：claim 拒绝话术细化与 worker 提示词增补为已批准的行为改进，policy 无关地生效——「完全一致」指上下文治理本身不引入默认行为变化）
- **Given** 全量既有测试，**When** 改造后运行，**Then** 原样通过，无一处断言修改。

### User Story 4: 子 agent 输出预算与失败证据（Priority: 中，P1）

并行调查的单份报告体积有界；调查者故障或预算耗尽时传回说明性证据而非让整轮失败。

- **Given** 某调查者的结论报告超过报告预算，**When** 回传给合成节点，**Then** 报告被截断并提示可按记录编号精确重查（查询去重支持同键重查补偿）。
- **Given** 某调查者因内部故障异常退出，**When** 并行批次收拢，**Then** 该任务产出含错误类型、错误信息与任务目标的错误报告，其余调查者照常，合成节点仍给出部分结论。
- **Given** 调查者因调用预算耗尽未产出报告，**When** 批次收拢，**Then** 产出预算说明报告（说明已推进到哪一步），而非静默缺失。

### User Story 5: 会话内记忆治理（Priority: 中，P2）

跨轮累积的结构化记忆不再单调增长：历史发现合并、过期证据淘汰。

- **Given** 跨轮发现清单超过条目上限，**When** 轮末组装检查点，**Then** 最旧的若干条合并为一条摘要条目（对象字段拼接保留改口作废的子串匹配语义），清单长度有界。
- **Given** 跨轮携带的检索证据超过体积/条数上限，**When** 下一轮恢复检查点，**Then** 按登记序淘汰最旧片段，本轮已检索证据（界面展示）不受影响。

## 需求

### 功能需求

- **FR-1**: 压缩触发为单一字符口径（可配置、缺省 0=关闭）；度量沿用 json.dumps 字符数近似，不引入分词器依赖（延续 002 FR-9）。试点建议值在冒烟校准后回填 quickstart。
- **FR-2**: 摘要为排查域五段结构模板；迭代合并以既有摘要作为输入、按「只增改」规则更新，不重复生成全量摘要；摘要正文超出字符上限时由代码截断至上限后落盘（软控制靠摘要要求中写明上限，截断为罕见兜底），结构化编号信封不受截断影响。
- **FR-3**: 切点纪律：整组压缩绝不拆散请求-结果配对；首条系统消息、任何用户消息、最后一段助手交换、既有摘要永不动。
- **FR-4**: 摘要持久化进检查点消息流（**修订 002 FR-8，见下节**）；事件日志 append-only 语义不变；投影每请求对当前消息流仍确定性重算（读路径语义不变）。
- **FR-5**: 摘要信封的结构化编号字段由代码从被删轮次的工具/用户消息确定性提取；编造防线所依赖的已见编号重建扩扫信封结构化字段（不扫描摘要正文）；防线判定规则本身不变（延续 002 FR-10）。
- **FR-6**: 压缩为全函数：任何失败（网络、输出不合规、畸形消息）一律跳过并留痕，绝不阻断本轮调查。
- **FR-7**: 压缩调用不计入模型调用预算，但用量诚实入账并标记为内部调用，事件可对账。
- **FR-8**: 直连节点的格式模板留在调用点；投影策略存在时仅对变量段做体积裁剪；用户问题永不截断；策略未配置时零改动。
- **FR-9**: 合成节点对每份调查报告设读取端上限；调查者产出端报告预算（P1）超限时截断并携带「可按编号重查」提示。
- **FR-10**: 调查者故障与预算耗尽产出说明性报告（含错误类型/信息/任务目标）；用户取消语义不受影响（取消照常上抛）。
- **FR-11**: 发现合并保留对象字段子串匹配语义，改口作废对合并条目仍命中。
- **FR-12**: 证据淘汰发生在检查点恢复时，只收敛跨轮携带；当轮证据展示不受影响。
- **FR-13**: 全部治理经设置键 opt-in，缺省关闭；新增核心模块只依赖标准库、模型协议类型与项目通用 JSON 工具。

### 对 specs/002 的修订（supersedes）

本特性将「检查点始终保存未压缩原生消息」修订为「检查点保存压缩后的消息流」。002 中以下位置受影响，plan 阶段须逐处标注 supersedes：

1. `spec.md` FR-8（检查点存未压缩原生消息）
2. `spec.md` US2 的「检查点里的消息仍是未压缩原生消息，投影重新确定性计算」
3. `spec.md` FR-3（投影边界表述中的「原生消息」）
4. `spec.md` FR-10（编号重建来源需补摘要信封）
5. `spec.md` 范围外「投影结果的跨轮缓存或增量压缩」（003 即持久化压缩）
6. `data-model.md` 检查点描述
7. `plan.md` 相应段落
8. `research.md` R-5 及被拒备选「投影结果持久化」的理由记录
9. `contracts/interfaces.md` §5 think() 描述
10. `tasks.md` T024（已完成，仅加注不改内容）

修订理由须预写：002 以「确定性重算」为由拒绝持久化投影输出；003 改写的是检查点消息流而非投影输出，投影对给定输入仍确定——002 的理由不是被推翻，而是边界移动。

### 关键实体

- **ContextPolicy（扩展）**: 压缩触发字符线、摘要正文字符上限（P0）；报告字符预算（P1）；发现条目上限、证据淘汰上限（P2）；未配置即现行为
- **会话摘要信封**: kind 标识 + 摘要正文 + 结构化编号清单 + 覆盖轮次范围；以普通系统消息形态存于消息流
- **调查发现条目**: 工具名/对象/行数/摘要，合并条目对象字段为成员拼接
- **治理留痕事件**: 压缩发生/失败事件，含压缩前后体积与轮次

## 成功标准

### 可度量结果

- **SC-1**: 默认配置下全量既有测试原样通过，模型请求内容与现行为逐字一致（例外注记同 US3：话术/提示词改进除外）。
- **SC-2**: 被压缩证据的记录编号由代码保证完整迁入摘要信封；压缩发生后跨轮引用 0 误拦；无来源编号拦截率保持 100%。
- **SC-3**: 压缩×投影组合下，配对完整/存活集合/畸形输入原样返回三条硬性不变量 100% 保持。
- **SC-4**: 直连节点开启策略时变量段截断带显式标记、用户问题原样；关闭时与现行为逐字一致。
- **SC-5**: 压缩调用用量可对账（事件可查、标记内部），且 0 次计入模型调用预算。
- **SC-6**: 调查者故障/预算耗尽场景中合成节点照常作答并给出部分结论（冒烟断言，P1）。
- **SC-7**: 发现清单 ≤ 上限且改口作废对合并条目命中；证据淘汰不影响当轮展示（P2）。
- **SC-8**: 压缩后体积比为冒烟统计指标（分析脚本报告每会话压缩次数与体积曲线；单案例不达标不算失败——摘要长度由模型决定、保护集可能本身超线）。
- **SC-9**: 全量质量门（静态检查 + 类型检查 + 测试 + 前端构建）通过。

## 假设与依赖

- 摘要生成使用当前会话同一模型，不引入独立摘要模型。
- 压缩开关由触发线配置 >0 决定启用（缺省 0=关闭）；开启后的试点建议取值与投影字符预算同量级（30000），冒烟后回填 quickstart.md。
- 压缩开启产生的含摘要检查点，在压缩关闭的配置下恢复亦无害：摘要为普通系统消息，模型读到一段标注清晰的进度摘要，无需迁移。
- 真机冒烟依赖模型 API 可用性：P0 批必做（校准触发线），P1/P2 批尽力/补做，不作为硬门禁（002 T027 补做先例）。
- 摘要正文字符上限（试点 4000）、报告读取端上限（试点 4096）、发现条目上限（试点 20）、证据淘汰上限（P2，试点值冒烟后定）均为可校准常量，spec 不锁死取值。
