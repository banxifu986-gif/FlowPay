# 规格：006 网关加固与上线增强

状态：草案（方向与范围已与 Ban 拷问确认；待 005 落地收尾后实施，实施时按 spec-kit 流程补齐工件）
前置：specs/005-merchant-auth-boundary 已实施收尾（鉴权、scope 注入、ACL、记忆隔离就位）。
参考设计：Codex 类型化失败分类（错误按类别映射恢复策略，而非笼统失败）→ 结构化错误与降级；Claude Code 反馈机制 → 反馈闭环。

## 背景

005 落地后系统具备安全内核，但仍缺上线形态的运营面：无限流配额（LLM 成本敞口）、上下文管理机制建成但默认关闭、检索纯向量（错误码/单号等 ASCII 精确词是向量弱项）、无用户反馈回路、模型失败处理笼统。本规格补齐网关与增强，形成完整内网上线形态。

## 目标

1. 用量守卫：每商户日回合预算 + 并发 1 + 全局日上限，超限结构化 429 + 友好降级文案。
2. 结构化错误与降级：失败分类映射恢复策略，统一错误响应 shape。
3. 上下文管理默认启用：002/003/004 机制按 smoke 校准数据回填 production 配置并默认开启。
4. 混合检索：pg_trgm 关键词路 + 向量路 RRF 融合，零新依赖。
5. 反馈闭环：每轮 👍/👎（可附言）入事件日志，前端按钮。
6. 内网全链路冒烟。

## 用户故事

- **US1（P0）用量守卫**：每商户日回合预算（可配置）+ 每商户并发 1 + 全局日上限；计量复用事件日志中的回合记录（002 已有 per-turn 用量投影）；超限返回结构化 429 + 友好文案（非笼统报错）。验收：预算耗尽后新回合被 429 拒绝且文案可读；并发第二请求被拒或排队（实施时定）。
- **US2（P0）结构化错误与降级**：失败分类（超时/限流/上下文超长/配额/模型 5xx）→ 映射重试退避 / 强制压缩（复用 004 reactive compact 的超长路径）/ 友好文案；统一错误响应 shape（与 005 的 401/403、本规格 429 一致）。验收：注入各类故障，分类正确、恢复策略按映射执行、用户可见文案友好。
- **US3（P0）上下文管理默认启用**：以 smoke 校准数据（`scripts/analyze_smoke.py`、`scripts/smoke_003_context.py`）回填 production 配置的 `context_*` / `memory_*` 参数，默认开启；基准/冒烟脚本显式声明所用配置，避免「默认变」导致的隐性偏差。验收：默认配置下长会话压缩/投影生效事件可见；基准不回归。
- **US4（P1）混合检索**：关键词路（Postgres `pg_trgm` GIN，零新依赖；中文文档 + ASCII 错误码/单号场景，trigram 对 CJK 子串可用）+ 向量路双召回，RRF 融合，Evidence 溯源字段（collection/doc/chunk/sha256/locator）不变；离线对比评测（错误码/单号类题目为目标，**不设硬线**）。备选：jieba+tsvector 需新增依赖，实施时再议。验收：融合检索通过既有验证脚本；300 题基准不回归。
- **US5（P1）反馈闭环**：每轮回答后 👍/👎（可附言）→ 事件日志新事件类型 append-only；前端按钮；**反馈不注入对话上下文**（防污染后续轮次）。验收：反馈事件落盘可查询；后续轮次上下文不含反馈内容。
- **US6（P2）内网全链路冒烟**：compose 全栈起 → 登录 → 提问 → SSE → 反馈 的 smoke 脚本；compose 预留反向代理服务位（注释态，不实现）。验收：冒烟脚本一键通过。

## 范围外

- TLS/域名/公网暴露、反向代理实现（仅预留位）
- 成本看板/管理后台、反馈数据的自动分析闭环
- 重排序模型（cross-encoder）、查询改写多路召回（agent 多轮检索已部分覆盖）
- 混合检索提升硬线（只设目标）；token 级精细计量计费

## 验收标准（总）

- 专项测试：限流/配额触发、错误分类映射、融合检索召回与溯源完整。
- **300 题基准不回归 = 硬门禁**；混合检索提升为目标非硬线。
- 内网全链路冒烟通过；`make quality` 全绿。

## Clarifications（已与 Ban 确认）

1. 增强四项全选：混合检索、反馈闭环、用量/成本守卫、结构化错误与降级；上下文管理默认启用也归本规格。
2. 基准不回归即硬门禁；混合检索提升只设目标不设硬线（提升幅度受数据集限制，避免反复拉锯）。
3. 关键词路首选 pg_trgm 零新依赖方案；备选 jieba+tsvector（需新增依赖）实施时再议。
4. 反馈不进对话上下文，仅作数据沉淀。
5. 限流粒度：每商户日回合预算 + 并发 1 + 全局日上限；具体数值实施时校准，均为可配置项。
