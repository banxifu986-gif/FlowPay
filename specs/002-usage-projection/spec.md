# Feature: 模型用量聚合与请求前上下文投影（pi 思想借鉴）

**Branch**: `feat/002-usage-projection`
**Date**: 2026-11-14
**Status**: 计划已定稿（2026-11-14 四项决议已回填），本 spec 沉淀需求与验收

## 用户场景与测试

### User Story 1: 每轮回答可见 token 用量（Priority: 高）

支持人员与前端用户在每轮排查后能看到本轮消耗了多少模型资源，用量数据可核查到调用记录。

- **Given** 一轮排查正常完成，**When** 前端收到本轮结果，**Then** 展示本轮模型调用次数与输入/输出 token 用量，数值与调用记录一致。
- **Given** 某次模型响应未携带用量（compatible 端点的既有行为），**When** 聚合，**Then** 该次记为缺失（空值）而非 0，其余有值部分正常聚合。

### User Story 2: 长会话排查上下文受控且引用可信（Priority: 高）

多轮长排查会话中，早前的大量工具结果不再原样全量发给模型，但回答对历史记录的引用仍可核查。

- **Given** 会话累计长度超过保守阈值且投影策略开启，**When** 系统发起下一次模型请求，**Then** 最老的完整轮次被压缩为占位摘要（含目标对象、行数、记录编号清单），请求体积受控。
- **Given** 回答引用了被压缩轮次的记录编号，**When** 提交前核对，**Then** 编号可从占位摘要清单核查到，不触发编造改写。
- **Given** 投影发生后本轮意外中断、从检查点恢复，**When** 下一轮继续，**Then** 检查点里的消息仍是未压缩原生消息，投影重新确定性计算。

### User Story 3: 默认行为完全不变（Priority: 高）

未配置投影策略时，系统行为与现状一致——这是本特性可安全合入的前提。

- **Given** 未配置上下文策略（默认），**When** 任意阶段处理任意会话，**Then** 发给模型的上下文与现行为完全一致。
- **Given** 全量既有测试，**When** 改造后运行，**Then** 原样通过，无一处断言修改。

### User Story 4: 跨轮引用不再误拦（Priority: 中）

上一轮工具真实返回过的记录编号，本轮回答引用时不被判为编造。

- **Given** 上一轮某工具返回过记录编号 X，**When** 本轮回答引用 X，**Then** 不触发编造改写，调查继续。
- **Given** 回答引用的编号既没有工具返回过、也不是用户给出的，**When** 提交前核对，**Then** 仍被拦截并要求改写（防线判定规则不变）。

### User Story 5: 并行调查下的投影隔离（Priority: 中）

multi-agent 并行调查中，每个调查者独立做投影，互不影响。

- **Given** 多个调查者并行持有各自独立的对话消息，**When** 投影策略开启，**Then** 各自的投影独立计算，一个调查者的压缩不影响其他调查者的请求内容。
- **Given** 任一模型请求发出，**When** 事后核查调用记录，**Then** 记录的是投影后实际发送的请求体。

## 需求

### 功能需求

- **FR-1**: 用量聚合为纯函数能力：从已持久化的模型响应记录聚合用量，产出按运行/会话维度的 {模型调用次数, 输入 token, 输出 token, 合计}；缺失字段记为空值，不记 0。
- **FR-2**: 每轮结果与实时推送携带本轮用量汇总；不新增记录类型，不改变检查点与预算的既有语义。
- **FR-3**: 投影是请求发出前的纯函数边界：每次模型请求前，把会话原生消息投影为实际发送的消息；上下文策略未配置（None）时，投影结果与原样全量发送逐条一致。
- **FR-4**: 投影的删除单元是"一条助手消息 + 它之后全部配对的工具结果"整组，绝不拆散请求-结果配对。
- **FR-5**: 投影永不删除：首条系统消息、任何用户消息、最后一段助手交换。
- **FR-6**: 被压缩的旧工具结果以占位摘要呈现，必须包含目标对象、行数与记录编号清单，不静默消失。
- **FR-7**: 投影是全函数：任何畸形输入（缺字段、配对破损、空列表）原样返回，绝不抛异常。
- **FR-8**: 检查点始终保存未压缩原生消息；投影结果不持久化，每轮确定性重算。
- **FR-9**: 体积度量用字符数近似，不引入分词器依赖；阈值默认极保守（只压缩最老的完整轮次），取值由模拟数据校准，试点后按真实用量微调。
- **FR-10**: 从检查点恢复时，编造引用防线所依赖的"已见编号"集合重建必须纳入历史轮工具真实返回过的编号（连同用户给出的编号）；防线判定规则本身不变。
- **FR-11**: manual-loop 与 multi-agent 两阶段同轮启用投影（可配置开关）；并行调查中各调查者独立投影。
- **FR-12**: 测试基座支持构造带用量字段的响应与多分片流式响应，使聚合、分片与投影路径都被测试驱动。

### 关键实体

- **用量汇总（UsageSummary）**：模型调用次数 + 输入/输出 token，容忍单次缺失。
- **上下文策略（ContextPolicy）**：投影开关与阈值；None 表示现行为，是所有既有路径的默认值。
- **占位摘要**：被压缩工具结果的替身，携带可核查的记录编号清单。
- **已见编号集合（seen）**：工具真实返回过 + 用户给出的记录编号，提交前核对的依据。

## 成功标准

### 可度量结果

- **SC-1**: 默认配置下全量既有测试原样通过，模型请求内容与现行为一致。
- **SC-2**: 用量聚合对含缺失用量的事件序列 100% 容忍（输出空值而非 0 或报错）。
- **SC-3**: 超阈值长会话场景中，投影后请求体积有界（预算为尽力目标：不可删集合自身超预算时存活不变量优先），四条硬性不变量（配对完整/存活集合/占位编号清单/畸形输入原样返回）100% 保持。
- **SC-4**: 跨轮引用回归中，历史轮真实返回过的编号 0 误拦；无来源编号拦截率保持 100%。
- **SC-5**: 并行调查场景各调查者投影互不影响；调用记录如实反映投影后请求体。
- **SC-6**: 全量质量门（静态检查 + 类型检查 + 测试 + 前端构建）通过。

## 假设与依赖

- 两阶段共用唯一模型请求入口是投影落点的前提（现状已满足，改造须维持单入口）。
- 模型响应的用量字段已在请求链路开启并随事件持久化，聚合不需要新的事件类型。
- 实时推送只推已持久化事件的约定不变。
- 阈值用模拟数据定保守默认，不阻塞实施；真实数据校准是后续动作，不是本特性的验收前提。
- multi-agent 并行调查中每个调查者持有独立的消息序列，投影在各自内部生效，不涉及共享状态的并发写。

## 范围外

- 多 provider 抽象、跨模型 handoff、系统消息分段 patch、运行中插话队列、hook 总线、分词器依赖。
- 投影结果的跨轮缓存或增量压缩（每轮确定性重算即可）。
- 工具级提前终止信号、工具执行中部分流、模型可见与机器可读结果双通道、弱格式参数垫片。
- 前端用量展示的具体交互设计（本期只保证契约数据可用）。
- 投影对 multi-agent 协调者提示词的针对性优化（本期统一策略）。
