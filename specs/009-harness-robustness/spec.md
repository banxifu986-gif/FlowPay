# 规格：009 harness 鲁棒性（失效降级、断点续跑、未证实标注、多跳检索）

状态：已澄清并审查修订（2026-11-22 grill + clarify；2026-11-23 外部审查 P0 事实修正与四项口径拍板回写；本轮只落文档不动代码，实施另起新分支）
前置：007/008 已收口入库（main）；008 多轮"最后一跳"假设已证伪关闭（Ban 拍板 2026-11-21）。
参考基线：R96B 臂（`var/benchmark/20261122-101317-2ca71c`）——总通过 20/96、证据全中 54/96、单轮 16/32、多轮 4/64、run.failed=1（嵌入 400 确定性拒绝）；A/B 详见 `specs/008-responses-reasoning/ab-report.md`。

## 背景

008 评测暴露的不足集中在 harness 行为与模型能力两层，本 spec 只处理 harness 层：

1. **真实失败形态（2026-11-23 审查经 R96B 事件库核实，修正初稿误诊）**：R96B 唯一 run.failed **不是**嵌入 400——那笔 400 已被 `investigate()` 的既有降级路径（specs/003 FR-10 error_report）消化，该轮正常完成。真实形态是 **synthesize 空输出**：末次调用返回 `[reasoning, message(空文本)]` 且无 `set_response` 决策，`answer_text` 抛 `ModelOutputError`，分类归 other（不可重试）直接 `run.failed`——一次模型抖动报废整题，且无重试机会。另有结构性缺口：worker 层 `investigate()` 的 catch-all 把工具错误一网打尽转 error_report，任务就此收束，不存在"以其余工具继续"；工具链路失败没有 run 内禁用登记、没有可观测事件，同一轮内后续任务还会对已失效链路重复发起请求。
2. **轮级检查点粒度过粗**：多 worker 并行调查中途失败时，本轮已完成子任务的查询、发现、证据全部丢弃，重试从头再来。检查点只有轮级一档。
3. **无证据也硬答**：FULL300 基线 110 题"证据齐断言零命中"、R96 逐题对照里"证据齐但断言零命中只翻 1 题"——模型的失败模式是硬答，而不是承认查不到。现有链路没有"结论必须带引用、无引用不输出"的结构性约束，提示词约束已被 008 证明到边际。
4. **计划与调查无边界约束**：plan 产出的任务与 worker 能力不匹配时原样流转；单个 worker 可以在单个任务上无限次调用工具跑飞。
5. **多跳检索第二跳断链**：R96B 多轮证据未中仍有 27 题，多跳题第二跳查询不带第一跳结论，检索盲查。检索侧可证实的收益上界是 full 口径 77.9% − actual 74.6% ≈ 3.3pp，LLM 查询改写不改变"收集了哪些事实"，不在此上界之内——不做。

**不在本 spec 的**：多轮断言表述瓶颈是模型能力问题（008 已证伪到"medium 档不够"），harness 只能做到"没证据不说话"，不能替模型写出命中必需断言的结论句。本 spec 不承诺通过率提升。

## 目标

1. 失效降级：失败分类新增确定性档位，驱动 run 内链路禁用与可观测事件；链路确定性失败时任务按"禁用即收束"携带发现返回；synthesize 空输出确定性重试一次、仍空则诚实占位完成；部分作答 + 未证实标注；`run.failed` 只留给硬失败（模型不可用、配额、上下文超限）。
2. 断点续跑：worker 子任务完成即增量落盘；失败恢复从断点继续，不重查已完成子任务。
3. 诚实作答：结论句必须带引用或未证实标注，无裸奔断言；查不到的子项明确说"未能核实"，不转等待、不虚构。
4. 能力边界：plan 任务-能力不匹配可改派；worker 工具调用有预算上限。
5. 多跳检索：第二跳查询携带第一跳结论值。

## 用户故事

### US1（P0）分级失效处置与降级作答

单题内模型输出失败或工具链路确定性失败时，轮次不整轮报废：已查到的部分照常作答，查不到的子项明确标注未能核实。

- **Given** synthesize 末次调用返回空正文或无决策（`ModelOutputError`），**When** 作答失败，**Then** 确定性重试一次；仍空则输出诚实占位文本并正常完成本轮，不产生 `run.failed`。
- **Given** 某工具链路发生确定性失败（FR-1 白名单，如嵌入服务对查询文本的结构性 400），**When** worker 触发，**Then** 登记该链路禁用并发 `tool.outage` 事件（载荷含 `failure_class=deterministic`），该任务按既有 error_report 路径收束（携带目标与失败说明）；本轮后续对该链路的调用立即失败返回、不再发起请求；其余任务不受影响。
- **Given** 模型本身不可用或配额拒绝，**When** 轮次执行，**Then** 仍按既有失败分类与 `run.failed` 终态处理（硬失败口径不变）。

### US2（P0）节点级断点续跑

调查中途失败后恢复时，已完成子任务的成果不丢失、不重查。

- **Given** 一轮调查含多个 worker 子任务，**When** 某子任务完成后轮次失败，**Then** 该子任务的已查询键、发现、证据已随流程增量落盘。
- **Given** 用户显式继续一个 `run.interrupted`/可恢复的失败轮次，**When** 重新执行，**Then** 从已完成子任务之后继续，不重查已完成子任务（事件序列可证明）；后端重启→`run.interrupted`→用户显式继续的既有语义不变。

### US3（P0）未证实断言的结构化校验

汇总输出前的引用校验由 harness 确定性执行，不依赖模型自判。

- **Given** synthesize 产出含结论句，**When** harness 解析引用标记（记录编号、片段引用），**Then** 无引用支撑的断言句被确定性改写为未证实表述或触发一次定向重写，不得原样输出。
- **Given** 某子项完全查不到证据，**When** 作答，**Then** 该子项按统一口径表述"未能核实"，不转 `waiting_user`、不虚构记录编号（编号真伪仍由既有编造核对机制管，引用校验只看标记存在性）。

### US4（P1）多Agent 最小约束包

- **Given** plan 产出的任务目标与目标 worker 能力不匹配（如文档 worker 被派查业务记录），**When** 任务分发，**Then** 改派给匹配的 worker 或触发一次重计划；重计划后仍不匹配的任务丢弃并记录，不影响其余任务。
- **Given** 单个 worker 在单个任务上的工具调用次数达到上限（可配置），**When** 达到上限，**Then** 收束该任务并携带已查发现返回，不整轮失败。

### US5（P1）多跳两段式检索

- **Given** 多跳任务的第一跳已查得结论值（如事件编号），**When** 构造第二跳检索查询，**Then** 查询自动携带第一跳结论值，不再盲查；单跳任务与无第一跳结论时不拼接，行为不变。

## 边界情况

- **全部工具链路同时失效（模型可用）**：各任务按 FR-2 逐一以 error_report 收束，synthesize 汇总为诚实占位作答并标注降级原因，不虚构、不转等待、不 `run.failed`；模型不可用才进硬失败。
- **synthesize 空输出**：重试一次后仍空 → 诚实占位完成（FR-12）；上下文超限、模型不可用等既有硬失败分类不适用重试+占位口径，仍走既有终态。
- **pending 与工具失效并存**：维持 clarify 优先——有 pending 就按既有回退转 clarify（等待轮带结论门保证其携带报告结论），工具失效说明并入该轮报告摘要；FR-7 的未证实口径仅约束无 pending 场景（2026-11-23 拍板）。
- **子任务重查幂等**：恢复续跑时已查询键去重沿用既有机制；同一子任务不产生重复查询事件。
- **引用校验误判**：只校验引用标记存在性，不校验编号真伪（真伪由既有编造引用核对机制负责）；无任何结论句可输出时降级为"未能核实"。
- **重计划后仍不匹配**：丢弃该任务并继续其余任务；丢弃计入事件日志可审计。
- **预算上限与调查耐心的关系**：上限只约束单任务工具调用次数，不改变"证据不全继续调查"的提示词约束；上限触发即收束，不追加等待。
- **多跳两段式的结论值污染**：第一跳结论值超长或含无关内容时截断/清洗后拼接（沿用既有 ≤500 字符口径）；拼接值取有序集合并排序，保证同一 findings 集合产出同一查询文本（恢复续跑时不因拼接顺序漂移而重查）。

## 范围外

- LLM 查询改写（收益上界被 full 口径 77.9% 封顶，不做）
- 跨会话全局熔断（单 worker 单写者部署无证据需求）
- 意图×题型×工具的完整能力声明矩阵（无失败样本支撑）
- 混合检索复评（保留既有开关，换语料后另行复评）

- 轮级"用户显式继续"改为自动重试（保持 006 语义）

## 需求

### 功能需求

- **FR-1**：失败分类新增"确定性错误"档位（白名单：①嵌入/检索服务对查询文本的结构性 4xx（400/422）；②请求参数被供应商确定性拒绝；429 限流仍属瞬时；新增白名单档位必须以测试固化）。档位的职责是**驱动 FR-2 的链路禁用判定并进入事件载荷**（`tool.outage` 携带 `failure_class`）——现状下模型类 400 已归 other 档（不可重试、不烧重试预算），本档位不改变既有重试语义，只补工具链路侧的判定与可观测性。
- **FR-2**：工具链路 run 内禁用：链路发生确定性失败（FR-1 白名单）时登记禁用并发 `tool.outage` 事件（载荷含 `failure_class` 与链路标识）；本轮剩余请求对已禁用链路的调用立即以失败终止该任务（复用既有 error_report 收束路径），不再发起请求；触发登记的任务本身按既有 error_report 收束（携带已查发现与失败说明），其余任务不受影响；禁用不跨轮、不跨会话。
- **FR-3**：降级作答：部分证据可得时输出部分作答——有证据子项正常回答，无证据子项统一表述"未能核实"；整轮正常完成；仅模型不可用等硬失败才写 `run.failed`。全部工具失效（模型可用）时各任务按 FR-2 逐一收束，synthesize 汇总为诚实占位作答。
- **FR-4**：节点级断点：worker 子任务完成即把该子任务的已查询键、发现、证据增量落盘（复用既有事件日志与检查点机制，不新增存储形态）；图节点幂等，恢复后跳过已完成子任务。恢复执行不新增日回合计量——同一轮次的恢复不重复计数，只补记实际发生的模型/工具调用。
- **FR-5**：恢复语义兼容：后端重启→`run.interrupted`→用户显式继续的既有对外行为不变；"继续"改为走节点级续跑路径。
- **FR-6**：引用校验：synthesize 输出前由 harness 解析结论句引用标记；无引用支撑的断言句确定性降级为未证实表述，或触发至多一次定向重写；校验为本地确定性解析，不新增模型调用（定向重写除外）。
- **FR-7**：未证实口径统一：查不到的子项表述统一、可被报表识别；不得以 `waiting_user` 替代未证实表述。被预算上限收束的未完成部分并入"未能核实"口径，收束原因（超限/禁用）仅在事件日志可查，作答中不单独区分。**本条仅约束无 pending 场景**：存在 pending（某 worker 已追问条件）时维持既有 clarify 优先回退，工具失效信息并入 clarify 轮的报告摘要（等待轮带结论机制门保证其携带结论）。
- **FR-8**：plan 任务-能力校验：分发前核对任务目标与 worker 能力；不匹配时改派或重计划至多一次；仍不匹配则丢弃并记录。
- **FR-9**：worker 预算上限：单 worker 单任务工具调用次数上限（配置项，默认值实施时定），超限收束并携带已查发现返回。
- **FR-10**：多跳两段式：第二跳查询自动携带第一跳结论值；结论值清洗沿用既有长度/格式口径；无第一跳结论时不改变现有行为。
- **FR-11**：下游零改动：上述机制不得改变既有事件类型、检查点形状、用量统计与前端投影的兼容性；新增信号（未证实标注、任务丢弃、预算收束）通过既有事件通道承载。
- **FR-12**：synthesize 空输出处置：末次调用无决策或空正文（`ModelOutputError`）时确定性重试一次（复用 003 编造核对 DISPUTE 的重试先例口径）；重试仍空则以诚实占位文本正常完成本轮，不产生 `run.failed`。上下文超限、模型不可用等既有硬失败分类不适用本条，仍走既有终态。

### 关键实体

- **失效分级（FailureClass）**：瞬时（可重试）与确定性（不可重试）二档，决定是否消耗重试预算。
- **工具链路禁用（ToolOutage）**：run 生命周期的工具可用性状态，随轮次终止清空。
- **未证实标注（UnverifiedMark）**：结论句的无引用降级表述，携带未能核实的对象与原因。
- **子任务断点（SubtaskProgress）**：单个 worker 子任务的已完成状态及其已查询键、发现、证据。
- **任务能力映射（CapabilityMap）**：worker 类型与可受理任务目标的对应关系，用于分发前校验。

## 成功标准

### 可度量结果

- **SC-1**：机制门不回归——整题覆盖率 ≥90%、重复问 0、等待轮带结论 100%（沿用 007/008 口径）。
- **SC-2**：96 题验收臂 `run.failed=0`（synthesize 空输出有 FR-12 占位兜底后可达）；注入白名单确定性错误的专项测试以**可证伪形态**验证——事件序列无 `run.retry`、`tool.outage` 载荷 `failure_class=deterministic`、整轮正常完成（防止用既有 error_report 路径"空跑通过"）。
- **SC-3**：降级作答契约——三个来源（工具链路禁用收束、预算收束、synthesize 空输出重试后占位）均整轮正常完成并输出部分作答 + 未证实标注，不产生 `run.failed`（专项测试证明）。
- **SC-4**：节点级续跑——中断恢复后已完成子任务零重查（事件序列证明：恢复后的查询键集合与断点前不交集）；轮级显式继续对外语义不变（既有测试全数通过）。
- **SC-5**：未证实标注契约——验收臂报表中无引用裸奔断言为 0（引用校验覆盖率 100%）；未证实子项以统一口径出现在作答中。
- **SC-6**：证据全中不降——同配置验收臂证据全中 ≥50/96（R96B 54/96 − 单次噪声 4 题）。
- **SC-7**：多跳检索改善——multi_hop 题证据全命中 ≥ R96B 基线（11/16），且第二跳查询携带第一跳结论值的机制在报表/事件中可验证。验收数据由 96 题全臂一次出数（与 SC-2/SC-5/SC-6 同臂），离线检索诊断只做机制抽查。
- **SC-8**：`make quality` 全绿；测试失败基线为空（不滚动）。

## 假设与依赖

- **验收臂配置**：沿用 R96B 口径（gpt-6-luna、responses + medium、bge-m3 集合），对照基线 = R96B 逐题结果；机制门统计沿用采纳轮口径。
- **费用量级**：引用校验与节点级断点为确定性机制零额外模型调用；多跳两段式只改查询内容不增调用轮数；预算收束预期减少调用量——整体不新增费用档位。
- **持久化复用**：子任务断点复用既有事件日志与检查点机制，不新增存储组件、不迁移数据。
- **无新依赖**：不新增第三方包。
- **实施分工**：Ban 另起新分支后按 tasks 实施；本轮仅交付文档。
- **resume 计量语义**：恢复轮的 `run.started` 载荷已含 `resumed` 标记（`_persist_run` 只跳过 message.user，不跳过 run.started）——"同轮不重复计数"落地为 `daily_run_count` 过滤 `resumed=true` 的 run.started，不新增事件类型（FR-11 优先）；并发预留保持对称（resume 提交仍预留并发名额）。
- **审查修正记录**：初稿背景把 R96B 的 run.failed 误诊为嵌入 400 烧重试——2026-11-23 外部审查经事件库核实推翻（400 走既有 error_report 降级正常完成；真实形态是 synthesize 空输出直接 run.failed）。US1/FR-1/FR-2/SC-2/SC-3 已按事实重写，两项默认拍板的外部行为（分级降级、run 内禁用）不受影响。
