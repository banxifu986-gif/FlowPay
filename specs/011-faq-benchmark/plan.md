**输入**：[spec.md](spec.md) ｜ **状态**：计划已编写，未实施  
**设计工件**：[研究与取舍](research.md) · [数据模型](data-model.md) · [接口与验收契约](contracts/faq-suite.md) · [快速验收](quickstart.md)

## 摘要

以独立冻结发布物绑定公开 FAQ、付款／退款快照及评测标注。显式 FAQ 装配从同一版本选取独立 collection 和本人记录范围，复用现有 `multi-agent` 与聊天页。评测按实际发布回答、证据和行为逐题计分；仅评测器持有金标，旧入口照常运行。

## 技术上下文与项目门禁

- 沿用 Python、pytest、现有 SQLite 只读来源、PostgreSQL 向量集合、现有模型客户端和 React 聊天页，不引入依赖或新模型协议。
- `scripts/` 管理制包、摄入和评测；`flowpay/bootstrap.py` 装配场景工具与提示；`workflows/` 不持有文件、SQL、连接客户端；通用数据来源、认证、事件能力留在 `core/`，不反向依赖脚本或场景。
- 复用现有登录、会话、SSE、引用和用量口径，不新增生产路由或前端页面。仅显式进入 FAQ 模式；本地后端只监听回环地址，使用独立会话状态和令牌密钥，关闭跨会话记忆。
- 成功门禁区分**数据质量、边界、判分正确性**和**模型能力**。前三项须通过；模型表现如实记录，不篡改评分、不调 test、不修 010 既有缺陷。
- 编码前在不触碰 010 未提交改动的实现工作区记录测试基线；先写可证伪的失败用例，再分模块实现。失败环境或缺依赖须明确记录，不作通过。规划阶段无代码改动，当前不运行项目测试。

## 分阶段实施及验收

| 阶段 | 实施 | 验收 |
| --- | --- | --- |
| A. 发布底座（US1） | 为 `flowpay-faq-dataset/` 建公开 FAQ 和合成源数据；在 `scripts/faq.py` 冻结独立 release、生成只读快照和运行视图；复用 `scripts/ingestion/` 构建 FAQ collection。 | 先用小样夹具；篡改、混版、错误组、路径逃逸和错误版号均拒绝；原数据不写入；运行视图不含题库金标。 |
| B. 本人取证（US1/US3） | 显式 FAQ profile 组合运行资料；给既有多 Agent 阶段注入受限的付款／退款查询能力和付款用户口径；授权范围来自认证主体。 | 两个身份验证正向查询、相同样式的跨身份／不存在空结果、拒绝无范围与内部主体；旧入口及事件契约回归。 |
| C. 独立评测（US2） | 现有 runner 保留默认行为，FAQ 显式读取自己 split；复用渐进披露，新增 FAQ 证据绑定、行为和逐断言语义判分。 | 固定正负夹具：命中但未引用、错误记录字段、错绑、错误版本、过早判断、复问、缺跳，以及运行／评分异常；每种失败可追溯。 |
| D. 正式内容与冻结（US1/US2） | 完成约 20 篇主题问答与 100 题、两类时间口径、dev/test 分组和金标评审；生成最终 release 与独立 collection。 | 两边精确保持主类配比、难度覆盖，近重复题／记录／脚本不跨 split；证据引用可解析、快照字段与金标一致。 |
| E. 本地演示与实测（US2/US3） | 复用本地 Web 页代理，先 dev 冒烟再跑完整 test，输出分型／难度诊断。 | 双身份浏览器验收及旧套件回归通过，报告逐题记录 60 道 test 真实执行与评分情况；报告不按模型通过率放行。 |

## 拟修改范围与非目标

- 发布与数据独立切片：`flowpay-faq-dataset/`、`scripts/faq.py`、`scripts/ingestion/` 的必要参数化和 `backend/tests/scripts/`。
- 运行与装配切片：`backend/src/flowpay/cli.py`、`flowpay/bootstrap.py`、`flowpay/workflows/multi_agent/` 的装配边界及现有 `core` 能力与对应测试。先核对可复用注入点，不复制既有阶段。
- 评测切片：`scripts/benchmark/` 与对应测试；报告和构建产物写 `var/faq/`，不提交 SQLite、分块、向量或运行日志。
- 不改原数据目录、默认设置、原问答计分及现有服务路由。不新增业务写入能力、不引入真实交易、改口或主动追问题，不自动上传发布物。

## 设计复核

通过隔离发布、受限主体、只读工具和评测输入分离满足安全边界；通过注入式回归验证用户实际可见的消息、引用和拒绝结果。需要交付的是一套可复跑的基准，不依赖原题库、010 在线审计开关或固定模型分数。
