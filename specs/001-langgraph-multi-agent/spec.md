# Feature: LangGraph 多 Agent 编排（意图路由 + 并行协作排查）

**Branch**: `feat/langgraph-s5`
**Stage 注册名**: `multi-agent`（替代教学序号 s5；现有阶段同步改名 `manual-loop`）
**Date**: 2026-11-12
**Status**: 已批准技术方案（见改造计划），本 spec 沉淀需求与验收

## 用户场景与测试

### User Story 1: 闲聊消息得到轻量回应（Priority: P1）

用户发来问候、感谢或询问助手能力时，系统直接回应，不触发任何业务查询，也不消耗调查资源。

- **Given** 会话处于任意状态，**When** 用户发送"你好，你能做什么？"，**Then** 系统以寒暄+能力介绍回应，本轮 0 次业务工具调用，已有的排查状态不受影响。
- **Given** 用户刚完成两轮排查，**When** 用户发送"谢谢"，**Then** 系统简短回应；下一轮继续排查时，此前的条件与查询结论仍然有效。

### User Story 2: 文档问题得到有引用的回答（Priority: P2）

用户询问平台规则或文档说明时，系统检索知识库作答，回答附带可核查的引用。

- **Given** 用户问"Webhook 重试策略是怎样的？"，**When** 系统回答，**Then** 回答引用了检索到的具体文档片段，且引用可在会话记录中核查。
- **Given** 文档检索无命中，**When** 系统回答，**Then** 明确说明未能找到依据，不编造引用。

### User Story 3: 排查问题由多个 Agent 并行调查（Priority: P1）

用户报告一个排查问题时，系统由协调者拆解调查方向，数据调查与文档调查并行开展，最后汇成单一结论。

- **Given** 用户说"有笔支付成功了但一直没收到通知，帮我看看"（缺条件），**When** 系统处理，**Then** 先向用户追问缺失条件，本轮结束等待输入。
- **Given** 条件齐全的排查问题（同时涉及业务记录与平台规则），**When** 系统处理，**Then** 两类调查并行执行，最终回答先给结论、再给依据记录、最后说明未能确认的部分。
- **Given** 某一调查方向发现需要向用户追问，**When** 本轮收束，**Then** 系统把追问提交给用户，等待输入，未完成的调查在下一轮继续。

### User Story 4: 跨轮状态与意图切换（Priority: P1）

用户在多轮对话中切换话题（排查→闲聊→排查）时，此前的排查条件与已得结论不丢失。

- **Given** 用户已提供账户与环境条件，**When** 用户插入一句闲聊后又回到排查，**Then** 条件仍生效，系统不重复索要。
- **Given** 用户改口换账户，**When** 系统处理，**Then** 旧账户下的编号作废，依赖旧值的结论不再使用。
- **Given** 上一轮执行过某个查询，**When** 本轮调查需要相同信息，**Then** 系统使用上一轮结论摘要，不重复执行相同查询。

## 需求

### 功能需求

- **FR-1**: 系统每轮自动判断用户消息意图，分为排查、文档问答、闲聊三类，无需用户手动选择阶段。
- **FR-2**: 消息中出现业务编号（按既定前缀规则）时直接进入排查，不产生额外分类开销。
- **FR-3**: 意图判断失败或无结论时，兜底进入排查（排查能力是文档问答的超集，路由错误代价最低）。
- **FR-4**: 排查任务由协调者拆解为子任务，数据调查与文档调查可并行执行；子任务为空时直接进入汇总。
- **FR-5**: 所有调查 Agent 共享统一的调用预算与查询去重；同一条件的同一查询在会话内只执行一次，重复请求被拒绝并提示使用已有结果。
- **FR-6**: 每次查询的结论以结构化摘要形式跨轮保留，供后续轮次的协调者与调查者参考。
- **FR-7**: 条件不足以发起查询时向用户追问缺失项，追问只针对未提供的字段，已提供的字段不重复索要；追问提交后本轮结束（waiting_user），不挂起执行。
- **FR-8**: 闲聊回应不调用任何业务工具或文档工具。
- **FR-9**: 文档问答的回答必须引用检索到的具体片段；无命中时明示依据不足。
- **FR-10**: 意图切换时跨轮排查条件保留，不清空。
- **FR-11**: 跨轮状态（已知条件、已执行查询、结论摘要、引用片段）在轮末持久化、轮初恢复；轮内编排状态不跨轮持久化。
- **FR-12**: 现有阶段更名为 manual-loop（单 Agent 手动编排循环），新阶段注册为 multi-agent；旧会话不做迁移，提交时明确报错引导新建会话。
- **FR-13**: multi-agent 为默认阶段，用户可配置回 manual-loop。

### 关键实体

- **意图决策（IntentDecision）**：意图类别 + 判断理由（理由仅用于追踪，不影响路由）。
- **调查任务（InvestigationTask）**：协调者拆解出的子任务，区分数据调查与文档调查。
- **调查报告（WorkerReport）**：单个调查 Agent 的产出，汇总时合并。
- **查询发现（Finding）**：一次查询的跨轮结论摘要（查了什么、命中多少、关键结论）。
- **共享轮次资源**：本轮全体 Agent 共享的预算、查询去重记录、已知条件、引用池、待追问项。

## 成功标准

### 可度量结果

- **SC-1**: 带业务编号的消息进入排查时，分类环节 0 次额外模型调用。
- **SC-2**: 闲聊消息本轮业务/文档工具调用次数为 0。
- **SC-3**: 同一排查任务中，两类调查并行执行的总轮内耗时不超过其串行执行耗时。
- **SC-4**: 回答中出现的业务/文档引用 100% 可在会话记录中核查到对应片段（无编造引用）。
- **SC-5**: 意图切换回归场景（排查→闲聊→排查）中，已知条件保留率 100%，无重复索要。
- **SC-6**: 会话内同一查询重复发起时 100% 被去重拦截。
- **SC-7**: 全量既有测试在改造后保持通过（含旧阶段回归）。

## 假设与依赖

- 多 Agent 编排采用已批准的 LangGraph 方案：仅接管轮内编排，不引入持久化 checkpointer；跨轮状态沿用现有 saved_state 通道。
- 所有图节点使用 async 定义，共享预算与去重的同步临界区依赖单事件循环原子性。
- 图状态在轮末组装为跨轮检查点，新增 findings 与 stop_reason 键；与既有检查点键（case/queried/evidence）语义兼容。
- 旧阶段（manual-loop）代码文件同步改名为 `manual_loop.py`，multi-agent 复用其条件累积、规则提取、查询去重、工具表与追问机制，不复制实现。
- 依赖版本锁定在已验证的小版本区间，防止编排 API 漂移。

## 范围外

- 旧会话数据迁移（Conflict 报错走前端已有路径）。
- 排查之外的新意图（如账户操作类）。
- Supervisor 跨意图的动态再分派（本期只做固定三意图路由）。
- 多模型差异化装配（保留接口能力，本期单模型实例）。
