# 规格：008 推理能力验证与检索收尾

状态：草案（2026-11-21 已与 Ban grill 确认范围与验收；spec-kit 全流程，Claude 直接实施）
前置：007 已收口入库（`feature/007-clarification-retrieval`）；全量 300 题基线已建立（FULL300 臂）。
参考基线：`var/benchmark/20261121-full300-*`——总通过 53/300（17.7%）、证据全中 167/300（55.7%）、多轮 9/180（5.0%）、单轮 44/120（36.7%）。

## 背景

全量 300 题基线暴露的最大短板是"从证据到结论的最后一跳"：**110 道失败题证据全中但断言零命中（多轮 92 题）**——检索走对、记录查对，回答里却没有一句命中必需结论；违规禁止结论为 0（模型没有说反话，是没说到位）。多轮通过率 5.0% 对比 DeepSeek 37.5% 的断崖，主因是推理能力缺失：无推理形态下模型直接从材料跳到回答，缺少"多材料综合成断言"的中间步骤。

当前聊天适配器只支持 chat/completions 协议；OpenAI 对推理模型的限制是：该协议上"function tools + reasoning_effort≠none"组合被 gpt-6 系列拒绝（服务端默认推理档位，无法绕过）。要开启推理必须走 Responses API——这是产品接入 gpt-6 系列推理能力的唯一路径。

另有两项已具备充分证据的收尾：混合检索在 qwen3 与 bge-m3 两个独立嵌入空间的两次全量评测中均与纯向量逐格相同（pg_trgm 关键词路对本数据集无增益）；KB-API-017 是唯一在任何检索口径前 20 片段都不出现的必需文档（数据集覆盖缺口）。

## 目标

1. 推理接入：产品具备经 Responses API 使用推理模型的能力，工作流层零改动。
2. A/B 验证：96 题推理臂对照无推理基线，量化推理对"最后一跳"的改善。
3. 收尾清偿：混合检索默认关闭；KB-API-017 缺口形成数据集侧补缺清单。
4. 费用可控：推理臂跑前先冒烟定预算，超限即停。

## 用户故事

### US1（P0）推理模型可用

排查、文档问答、闲聊三类请求都能经 Responses API 正常完成——工具调用、流式输出、用量统计与现有 chat/completions 路径行为一致；开启推理后每轮决策（拆任务、追问、作答）质量不低于无推理形态。

- **Given** 会话配置为推理模型，**When** 用户发起排查问题，**Then** 意图路由、任务拆解、调查、汇总全链路正常，与无推理形态的行为边界一致（等待/完成状态、事件类型、检查点形状不变）。
- **Given** 模型在推理中决定调用工具，**When** 工具结果返回，**Then** 模型能带着推理上下文继续，不丢失前序推理链。

### US2（P0）推理增益可量化

推理臂与无推理基线在同 96 题上对照，"最后一跳"短板的改善程度可测量。

- **Given** 无推理基线中 110 题证据齐但断言零命中，**When** 推理臂跑同 96 题样本，**Then** 多轮通过率、断言命中数与基线逐题对比，翻盘题数与回退题数分别列出。
- **Given** 推理臂完成，**When** 汇总报告，**Then** 机制门三项（覆盖/重复问/带结论）不回归，用量与耗时相对无推理臂的倍数明确记录。

### US3（P1）混合检索默认收口

混合检索开关默认关闭，保留手动开启能力；默认配置下的检索行为与两次全量评测的纯向量结果一致。

- **Given** 新部署按默认配置启动，**When** 检索文档，**Then** 走纯向量路径（与 bge-m3 全量基线口径一致）。
- **Given** 运营方显式开启混合检索，**When** 检索，**Then** 功能仍可用，不因默认关闭而失效。

### US4（P1）数据集缺口可见

KB-API-017 缺口形成数据集侧可执行的补缺清单，产品代码不改动。

- **Given** 检索诊断报告列出的不可召回文档，**When** 产出补缺清单，**Then** 清单包含缺失文档编号、所属知识域、建议补充的来源与验证方式（重建集合后用检索诊断复查）。

## 边界情况

- **推理中工具调用**：模型决定调工具时，当前轮的推理内容（加密字段）必须随下一请求回传，否则推理链断裂；缺失时按无推理项降级继续，不报错。
- **流式中断**：流结束但缺少完成事件视为中断，不把已收到的部分文本当成功（与 chat/completions 口径一致）。
- **供应商拒绝**：Responses API 返回不支持参数（如某些模型不支持某档推理强度）时，错误按既有失败分类处理，不静默降档。
- **多档推理切换**：同一会话内不切换推理配置；配置变更经会话重建生效。
- **混合检索手动开启**：默认关闭后手动开启仍走完整关键词路，行为与 006 实现一致，不因收口而退化。
- **KB-API-017 引用题作答**：补缺清单完成前，引用该文档的题按现有失败口径处理，不做产品侧兜底。

## 范围外

- 全量 300 题推理臂（若 96 题验证显著有效，另行立项全量确认）
- 商户门户深化（会话历史、反馈可视化等用户可感知功能）
- 其他供应商的推理协议适配（Anthropic 原生、火山 Responses 等）
- previous_response_id 服务端续话模式（追踪可读性优先，完整重放口径已定）
- KB-API-017 数据文件的实际补录（数据集侧作者职责）

## 需求

### 功能需求

- **FR-1**：产品支持通过 Responses API 调用推理模型，能力包括：多轮对话、工具调用、流式输出、用量统计、失败重试语义——与现有 chat/completions 路径对外行为一致。失败分类与重试复用既有体系（006 的失败分类器）：适配层上抛异常，不自带重试。
- **FR-2**：多轮上下文采用完整重放：每次请求携带全部历史（含推理项的加密回传字段），不使用服务端会话状态；追踪事件中的请求体保持完整可读。原始流帧照既有口径全量落库（可回放、可审计）。
- **FR-3**：推理强度可配置（低/中/高三档），默认中档；经既有模型扩展参数通道配置（与现有配置机制同层），Responses 适配器消费该参数，不新增配置机制。
- **FR-3a**：协议选择经配置分流：模型配置新增协议项（chat_completions / responses 两种），装配层按该值选择适配器实现；两套实现长期并存，回滚 = 改一行配置；不按模型名做隐式判断。
- **FR-4**：适配层实现不得向下传染：工作流编排、提示词、状态机、基准脚本均通过既有模型调用接口使用推理模型，无感知协议差异。
- **FR-5**：推理模型的输出与既有链路兼容：工具调用解析、编造引用核对、澄清状态更新、决策事件等下游消费方不需要修改。Responses 流聚合成与现有内部响应完全相同的形态（消息、工具调用、用量、完成原因四要素）；推理内容存于响应扩展字段，不进入展示文本。
- **FR-6**：`knowledge_hybrid` 默认值改为关闭；开启路径保留，配置注释记录两次全量评测的证据。
- **FR-7**：KB-API-017 补缺清单落成交付文档，包含：缺失文档编号、引用它的题目清单、建议补充内容的知识域与要素、验证步骤。
- **FR-8**：推理臂运行前必须先完成 6 题冒烟：实测单题耗时与 token 用量，外推 96 题总量；实际用量超过外推值 2 倍时停止运行并报告。

### 关键实体

- **推理配置（ReasoningEffort）**：低/中/高三档的模型请求参数，随模型配置分发。
- **响应流（ResponsesStream）**：Responses API 的流式事件序列——输出项增删、文本增量、工具调用参数增量、推理摘要与加密内容、完成状态；聚合为既有内部响应形态。
- **基线对照（BaselineComparison）**：推理臂与无推理基线的逐题对照——翻盘题、回退题、新增证据命中的分布。
- **补缺清单（DatasetGap）**：单篇缺失文档的元数据与补录指引。

## 成功标准

### 可度量结果

- **SC-1**：推理臂机制门不回归——多轮发问题覆盖率 ≥90%、重复问 0、等待轮带结论 100%。
- **SC-2**：推理臂端到端方向性达标——总通过 ≥23/96、多轮通过 ≥17/64（无推理基线为总 19/96、多轮 9/180 折算口径）。
- **SC-3**：适配层行为一致性——推理路径与无推理路径在工具调用、事件类型、检查点形状上 100% 兼容（专项测试证明）。
- **SC-4**：A/B 报告给出翻盘量化——110 题样本中的翻盘数、回退数、新增证据命中数，以及多轮通过率的前后对比。
- **SC-5**：混合检索默认关闭后，默认配置检索与 bge-m3 全量基线的纯向量口径一致（抽查对照）。
- **SC-6**：KB-API-017 补缺清单完成，含验证步骤。
- **SC-7**：`make quality` 全绿；测试基线（当前 513 passed / 5 skipped）保持失败集合为空。

## 假设与依赖

- **模型口径**：推理臂与无推理基线同用 gpt-6-luna（同供应商同密钥），唯一差异是推理开关——排除模型差异对 A/B 的污染。
- **嵌入空间**：沿用 bge-m3 集合（`flowpay_docs_v1_bge_m3`），不重建；知识集合与检索路径在本特性中除开关默认值外不变。
- **基线复用**：无推理基线直接复用 FULL300 的 96 题样本子集（每类前 16 题），不重跑无推理臂。
- **费用量级**：无推理基线 96 题实测 prompt 19.28M/300 题（约 6.2M/96 题外推）；推理形态预计 prompt 增 2–4 倍、completion 增 1–2 倍，冒烟后定实际预算。
- **实施分工**：Claude 直接实施并自验；每批完成后向 Ban 提交验收报告。
- **无新依赖**：OpenAI SDK 已在依赖中；不新增第三方包。

- Q: chat/completions 与 Responses 两条路径怎么共存？ → A: 模型配置新增协议项（chat_completions / responses），装配层按配置选择适配器；两套实现长期并存，回滚 = 改一行配置，不按模型名隐式判断。
- Q: Responses 路径的失败重试怎么处理？ → A: 复用既有失败分类器（006），适配层只上抛异常，不自带重试。
- Q: Responses 流的聚合产物用什么形态？ → A: 聚合成与现有内部响应完全相同的形态（消息/工具调用/用量/完成原因），下游零改动；推理内容存扩展字段不进展示文本。
- Q: Responses 路径的原始流帧要不要照旧落库？ → A: 照 chat/completions 口径全量落库，可回放可审计。
- Q: 推理强度的配置通道怎么选？ → A: 复用既有模型扩展参数通道，不新增配置机制。
