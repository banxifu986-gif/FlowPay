# 功能规格：FlowPay 检索链路优化（变体改写 + 精排对照 + ID 关键词路）

**特性目录**：`012-retrieval-upgrade`
**创建日期**：2026-11-24
**状态**：已澄清（grill-me），待计划
**目标**：在不改变既有回答与判分契约的前提下，用离线实验驱动检索召回与精排改造：查询变体多路改写上线、按数据决定精排（rerank）与 ID 关键词路是否实施，并把 FAQ 基准与旧题库复跑对比作为端到端验收。

## 澄清记录

### 2026-11-24（grill-me）

- Q: 需求落在哪个载体？ → A: 新开 012 spec，走 spec-kit 流程；011 的 FR 条款与题库零改动。
- Q: 「查询改写扩展」指哪些维度？ → A: 多路变体改写（LLM 生成 2-3 个检索变体 + RRF 融合）；横向扩出口与 FAQ 专用改写不在本期。
- Q: 变体多路挂在哪一层？ → A: 检索客户端层统一实现，排查轮 / doc_qa / 单 agent / FAQ 模式全透明生效。
- Q: 变体生成方式与成本？ → A: 每次检索都生成变体（+1 次模型调用），复用现有对话模型配置，接受该成本。
- Q: 变体与 rerank 的实验顺序？ → A: 先变体后 rerank——rerank 在变体口径的 top20 存档上重排，两层不抢同一块排序空间导致虚高。
- Q: 离线测用什么题库？ → A: 旧 96 题先行（与 007 历史基线可比），FAQ dev 40 题就绪后补测（作为交付验收项）。
- Q: 达标判据？ → A: 变体 recall@10 ≥+10pp 且单轮不降才实施；rerank 在变体后基准 ≥+5pp 且单次延迟 P50 ≤500ms 才进实施决策。
- Q: BM25 处置？ → A: 原「关键词路 ~0」归因修正为整句 ILIKE 结构性失效；升级为 ID 对照实验（ID 拼接口径 + 逐 ID 匹配对照路），ID 口径 ≥+10pp 即实施逐 ID 关键词路，不引入 jieba/zhparser；不达标才留文字触发条件。
- Q: rerank 组件选型？ → A: 与 embedding 同供应商的 rerank API（同技术栈，零本地推理依赖）；离线测阶段只写报告脚本，实施阶段才落组件。
- Q: 与 011 基线的时序？ → A: 011 先按现链路跑正式基线（报告标注检索配置版本），012 改造上线后用同一 60 题 test 复跑对比，作为 012 的端到端效果验收。

## 用户场景与验收

### US1 — 离线变体实验与 top20 存档（P1）

维护者能在旧 96 题库上运行扩展后的离线检索评测，量化「查询变体多路」相对 initial 口径的召回增益，并把每次检索的前 20 片段存档供复跑与后续精排对照。

**独立验收**：同一命令复跑产出一致结构的报告；报告含变体口径曲线、与 initial 的差值、逐题型分解和达标判定；存档文件可被后续脚本独立读取。

1. **给定** 旧 96 题库与就绪知识集合，**当** 运行离线评测，**则** 报告同时给出 initial 与变体口径的 recall@k 及差值，判定线（≥+10pp 且单轮不降）在报告里可见。
2. **给定** 变体生成依赖对话模型，**当** 离线评测运行，**则** 生成的变体文本随存档落盘，同一题的变体在复跑时可直接复用存档，不重复调用模型。
3. **给定** 存档包含每次检索的前 20 片段，**当** 精排对照脚本读取存档，**则** 无需重跑检索即可计算精排前后的 recall@k。

### US2 — 变体多路检索上线（P1）

真实聊天与 FAQ 模式的任何知识检索（排查轮工具、文档问答、单 agent）自动获得「原句 + 2-3 个变体」的多路召回与融合去重；变体生成失败时行为与现状完全一致。

**独立验收**：开启改造后任选一个检索出口发起提问，回答引用的片段与单路相比不劣化；人为制造变体生成失败，检索仍按原句单路完成并正常作答。

1. **给定** 用户提出可检索的问题，**当** 检索执行，**则** 多路结果融合去重后返回的条数与单路一致，重复片段只出现一次。
2. **给定** 变体生成失败或超时，**当** 该次检索执行，**则** 回退为原句单路检索，不产生额外错误输出或中断。
3. **给定** 变体与原句内容相同或近似重复，**当** 多路执行，**则** 重复变体被剔除，不重复检索与计费。

### US3 — ID 关键词路对照实验与实施（P1）

维护者能用「ID 拼接口径」测出关键词路的真实收益：把真实业务记录编号拼进查询后，对照「逐 ID 匹配」路是否把含编号的证据召回上来；按数据决定是否实施。

**独立验收**：报告含 ID 拼接口径与逐 ID 对照路的 recall@k 对比与判定；判定达标时逐 ID 关键词路进入实施并有测试门禁，不达标时 spec 记录明确触发条件。

1. **给定** 查询携带精确业务记录编号，**当** 现有关键词路执行，**则** 实验能证明或证伪其能否命中含该编号的证据（现口径预期无法命中，须有数据佐证）。
2. **给定** 逐 ID 对照路抽取查询中的记录编号逐个匹配，**当** ID 拼接口径评测运行，**则** 报告给出该路的 recall@k 及相对现有关键词路的差值。
3. **给定** ID 口径增益 ≥+10pp，**当** 实施决策执行，**则** 逐 ID 关键词路上线，且不引入分词器或全文索引迁移依赖。

### US4 — 精排对照实验（P2）

维护者能在变体口径的 top20 存档上运行精排（rerank）离线对照，测出剩余排序空间与延迟代价，数据达标才进入实施决策；不达标则只留报告与触发条件。

**独立验收**：报告含精排前后 recall@k、单次延迟统计与判定（≥+5pp 且 P50 ≤500ms）；未达标的结论写明「维持现状 + 触发条件」，不虚报上限收益。

1. **给定** 变体口径存档，**当** 精排对照运行，**则** 报告给出重排前后 recall@k 对比、逐题型分解与单次延迟分布。
2. **给定** 精排判定未达标，**当** 实验结束，**则** 不实施精排组件，报告与触发条件沉淀为决策依据。
3. **给定** 精排判定达标，**当** 实施决策执行，**则** 精排组件进入 plan 阶段定型，组件与配置有明确依赖清单。

### US5 — FAQ 补测与 011 基线复跑对比（P2）

012 的产品改造上线后，先用 FAQ dev 题库补一轮离线实验验证增益在新数据形态上成立，再用 011 正式基线的同一 60 题 test 复跑端到端对比，形成版本可追溯的效果证据。

**独立验收**：两份报告均标注题库版本与检索配置版本；对比报告能区分检索增益与模型波动，未运行或异常的题不冒充成绩。

1. **给定** FAQ dev 40 题就绪，**当** 补测运行，**则** 变体/ID/rerank 三组对照在 FAQ 题库上重测，结论与旧题库结论并列呈现。
2. **给定** 011 正式基线（60 题 test）已跑，**当** 012 改造上线，**则** 同题库复跑并产出对比报告，标注两侧检索配置版本。
3. **给定** 复跑出现异常或未评到题，**当** 对比报告生成，**则** 异常单独列出，不计入通过成绩。

## 边界场景

- 变体生成的模型故障、超时或输出不可解析：一律回退原句单路，检索链路不得因变体而失败。
- 查询本身已是高度精确的编号/术语串：变体不得丢弃原句；原句必须始终参与多路召回。
- 关键词路改造不得让向量路已命中的证据掉出返回名额（沿用现有融合保护）。
- 精排对照只消费存档，不在线调用；延迟统计与在线路径的换算在报告里说明口径。
- 任一实验未达标：实施不发生，结论与触发条件必须可追溯，不允许静默丢弃或反复重跑凑指标。
- 评测标注、题库元数据永远只是评测材料，产品运行时不读取。

## 需求

### 功能要求

- **FR-001**：离线检索评测扩展变体口径与 ID 口径：在现有评测框架上新增「变体多路」（原句 + 模型生成的 2-3 个检索变体分别检索后融合去重）与「ID 拼接 / 逐 ID 对照」查询口径，产出 recall@k 对比、逐题型分解与达标判定；判定线在报告中可见。
- **FR-002**：离线评测把每次检索的前 20 片段与对应查询文本（含变体）存档为可复跑的结构化文件；同一题变体可复用存档，不重复调用模型。
- **FR-003**：检索通道统一接入变体多路召回：原句必须始终参与；变体与原句去重；融合去重后返回条数与单路一致；既有融合保护（向量路已命中的片段不被挤出名额）保持不变。
- **FR-004**：变体生成失败、超时或输出不可解析时回退原句单路检索，检索链路不因此失败，不产生额外错误输出；回退路径有测试覆盖。
- **FR-005**：ID 对照实验：以「真实业务记录编号拼进查询」的口径评测现有关键词路与逐 ID 匹配对照路；ID 口径增益 ≥+10pp 时实施逐 ID 关键词路，不引入分词器或全文索引迁移依赖；不达标时在 spec 内记录明确触发条件（何种信号、用什么口径复测）。
- **FR-006**：精排对照实验在变体口径 top20 存档上离线重排，报告重排前后 recall@k、逐题型分解与单次延迟分布；≥+5pp 且 P50 ≤500ms 才进实施决策，否则只留报告并记录触发条件；精排组件选型与依赖清单在 plan 阶段定型。
- **FR-007**：产品改造（变体多路、逐 ID 关键词路、精排）每次上线前须过全量测试基线与原套件回归检查；011 的 spec 条款、题库与判分逻辑零改动。
- **FR-008**：FAQ dev 40 题就绪后，三组对照（变体 / ID / 精排）在 FAQ 题库补测一轮，结论与旧题库结论并列，作为 012 交付验收项。
- **FR-009**：012 改造上线后用 011 正式基线的同一 60 题 test 复跑对比，报告标注两侧检索配置版本；异常与未评到题单独列出，不计入通过成绩。

### 交付顺序

| 阶段 | 内容 | 出口判据 |
| --- | --- | --- |
| ① 离线实验 | 变体口径 + top20 存档（旧 96 题） | 变体 ≥+10pp 且单轮不降 |
| ② 变体实施 | 检索通道变体多路 + 回退门禁 | 全量测试与原套件回归通过 |
| ③ ID 实验 | ID 拼接 + 逐 ID 对照（旧 96 题） | ID 口径 ≥+10pp 即实施，否则留触发条件 |
| ④ 精排对照 | 变体口径 top20 重排 | ≥+5pp 且 P50 ≤500ms 才进实施决策 |
| ⑤ FAQ 补测 | FAQ dev 40 题三组对照重测 | 新旧题库结论并列 |
| ⑥ 端到端对比 | 011 同 60 题复跑 | 对比报告含版本标注 |

## 成功标准

- **SC-001**：离线报告一次命令可复跑，含变体 / ID / 精排三组对照、逐题型分解与达标判定；存档结构可被后续脚本独立读取。
- **SC-002**：变体多路上线后原套件全量测试基线与原套件回归检查通过；人为制造变体失败时检索行为与现状一致。
- **SC-003**：ID 实验给出「能否命中含编号证据」的可检验结论；实施或触发条件二选一落档，无死条款。
- **SC-004**：精排对照给出剩余空间与延迟的真实数据；未达标时报告明确「维持现状」，不虚报上限收益。
- **SC-005**：FAQ 补测与 011 复跑对比报告齐全，题库与检索配置版本标注清晰，异常题不冒充成绩。

## 关键实体

- **检索变体**：由原句派生的 2-3 条等价检索查询；原句始终保留，变体去重后参与多路召回。
- **检索存档**：评测运行产生的查询文本、变体与前 20 片段的结构化记录，可复跑可重排。
- **达标判定**：每项实验的增益阈值与单轮不降底线，连同判定结果写入报告。
- **触发条件**：未达标实验留档的复测信号与口径；被后续评测引用时不得失义。

## 假设与范围

- 变体生成复用现有对话模型配置，每次检索 +1 次调用为已接受成本；精排组件与 embedding 同供应商栈，零本地推理依赖。
- 本功能不改既有回答、澄清、取证与判分契约；检索行为变化仅限召回与排序层面。
- jieba/zhparser 全文索引迁移、BM25 全量替换不在本期；仅当 ID 实验证明逐 ID 匹配不足时另行立项。
- 011 交付不被 012 阻塞：011 先跑正式基线，012 上线后复跑对比。
- 多轮评测口径的模型能力提升、上下文管理改造不在本期。
