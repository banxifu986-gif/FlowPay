状态：实施中（2026-11-23 grill 10 决策 + clarify 4 增量；双工作树开发已合并，Code Review NO-GO→P1×3+P2×7 已清偿（P1-1/2/3 + P2-1/3/4/7；P2-2/5/6 记录已知债，见 tasks Phase 8 与 review-report.md）；T019 冒烟待跑）

参考基线：R96B → R96B2（009 交付报告 §1-2）：总通过 20/96 持平、证据全中 54→56/96、断言覆盖 57→47/176（-10：temporal_versioned -4、tool_use_diagnostic -4）、run.failed 1→0、费用 +12%/+11%。

## 背景

009 相对 008 评测提升有限，诊断结论（grill 会话拍板）：问题不在"有没有引用"，而在**"引用里的哪段原文，能支持断言里的哪些条件"**。现有两层校验都不看语义：引用标记校验只验引用标记存在性（无标记→未能核实），编造核对只验记录编号真伪。断言覆盖 -10 的主要失败形态是**表述越界**——引用是真的，但表述扩大了适用对象（"企业版通常 5 个工作日"被写成"所有用户最多等 5 天"）、把"通常"写成保证、丢了"工作日"。这类失败既不靠检索侧（证据已召回）也不靠 prompt 约束（008 已证伪到边际）。

三层 harness 方案（Ban 设想）：证据可定位（evidence_id 登记）→ 逐断言校验（支持/部分支持/矛盾/证据不足，含反证）→ 校验结果控制发布（放行/收紧/补查/降级）。

现状核对（grill 会话代码事实）：

- 证据登记已存在大半：片段有稳定 id（`doc:KB-XXX#cNNN`）、段落定位、sha256、集合绑定数据版本；跨轮携带上限 200 条/40000 字符——"分配 evidence_id"不需要从零做。
- 草稿与证据已落事件：模型响应事件载含完整 completion 正文；知识检索响应事件保留全部溯源字段——**旁路回放不需要重跑 agent 循环**。
- 校验空缺：无逐断言语义校验；片段引用（`KB-XXX#cNNN`）的真伪无人核对（只有记录编号有编造核对）。

**不在本 spec 的**：检索链路任何改动（召回/查询改写/混合检索）；定向补查的执行（只记录建议，待回放报告证实收益后另行立项）；worker 阶段报告与单 agent 阶段的接线；多轮断言表述的模型能力提升；评测判分逻辑改动（子串匹配口径不动）。

## 目标

1. 发布前校验器：最终作答过"断言抽取+绑定 → 代码验 ID → 批量语义校验（四档）→ 处置"，旁路为主，在线开关默认关。
2. 断点归因：96 题旁路回放产出断点分布（没召回/绑错/表述越界/矛盾）与通过题误伤基线。
3. 判定质量可观测：校验器判定、处置、fail-open 全部落事件，回放报告可抽检。

## 用户故事

### US1（P0）逐断言校验与处置（在线档）

最终作答在发布前被逐断言校验：有原文支撑的带引用放行，越界的收紧，撑不住的诚实降级。

- **Given** 开关开启且最终作答产出，**When** 校验器执行，**Then** 每条带引用断言获得四档判定（支持/部分支持/矛盾/证据不足）与处置（放行/收紧替换/降级未能核实），判定与处置落事件。
- **Given** 部分支持判定附越界维度定位（对象/时间/数字/适用条件），**When** 处置，**Then** 以校验输出的收紧表述做句级替换；替换句中的数字与编号必须为原句与绑定证据的子集，越界则该句降级不替换。
- **Given** 部分支持判定缺越界维度定位，**When** 处置，**Then** 不收紧只降级（防线：宁可降级不盲改）。
- **Given** 校验器任一环节失败（调用失败/输出解析失败），**When** 在线档执行，**Then** fail-open 放行原文并记录事件，不阻断回答、不产生 `run.failed`、不改变轮次终态。
- **Given** 断言与证据矛盾，**When** 处置，**Then** 降级"未能核实"，分歧详情（冲突双方出处与冲突点）落事件载荷与回放报告，不在回答中呈现分歧。
- **Given** 无断言可抽取（纯操作指引/客套话回答），**When** 校验器执行，**Then** 零判定直接放行，不降级。

### US2（P0）旁路回放与断点归因（评测侧）

用真实失败样例离线回放校验器，把失败断点归为可行动的类别。

- **Given** 009 验收臂事件库，**When** 全量旁路回放，**Then** 从事件恢复草稿与证据（不重跑 agent），重放确定性校验链得到与在线同构的输入，每题产出逐断言判定 JSONL。
- **Given** 题库标准证据映射，**When** 断点归类，**Then** 规则：部分支持→表述越界；证据不足＋期望证据不在本轮片段集→没召回；期望证据在集但未绑定→绑错；矛盾→独立档；汇总报告给出四类断点分布与逐条样例。
- **Given** 通过题（task_pass=true），**When** 回放，**Then** 产出误伤基线：正确断言被误判为部分支持/矛盾的比例与逐条样例，作为开启态 go/no-go 依据。

### US3（P1）在线接线与开关

- **Given** 开关关闭（默认），**When** 最终作答发布，**Then** 行为与事件与 009 完全一致（零新增调用、零新增事件）。
- **Given** 开关开启，**When** 校验执行，**Then** 判定与处置经新增事件类型落既有 JSON 事件通道；不改既有事件类型、检查点形状、用量统计口径；校验调用计入既有用量记录。

## 边界情况

- **校验器与既有校验的叠加**：接线在既有统一作答出口之后、发布之前；输入为经既有引用标记校验后的文本；已带未证实口径的句子跳过逐断言校验；片段引用 ID 真伪由 FR-3 补上（记录编号真伪仍归既有编造核对机制）。
- **处置幂等**：处置后文本再过校验器不二次改写（沿用既有引用校验的幂等先例）。
- **多轮会话**：每轮作答类回复都校验；澄清追问不校验。
- **收紧改写与判分的相互作用**：R96B 子串判分对改写敏感（改写可能丢原子串、新表述不精确命中）——防线②子集校验 + 冒烟误伤基线是 go/no-go 依据；降级格式沿用"未能核实：原句"保留原句口径，不影响子串命中，只增加未证实计数。
- **回放与在线的同构性**：回放恢复的是**原始草稿**并重放确定性校验链，不是直接拿发布文本校验——保证回放结论可迁移到在线档。
- **降级与占位作答**：synthesize 空输出占位（009 FR-12）等已带未证实口径的整段作答直接跳过校验（零断言放行路径覆盖）。
- **记录摘录缺失**：断言引用记录编号但事件库无对应记录（或记录数据为空）→该维度按证据缺失参与判定，涉及该编号的断言按"证据不足"处置；不阻塞其余断言的校验。
- **预算耗尽**：轮次预算耗尽时跳过校验并记录事件（等效 fail-open 口径）；校验器调用计入既有用量记录，不挤占 worker 工具调用预算（009 FR-9 口径不变）。

## 范围外

- 定向补查的执行（只记录建议动作；收益待回放报告证实后另行立项）
- worker 阶段报告的逐断言校验、单 agent 阶段接线
- 模型能力提升（多轮断言表述瓶颈，008 已关闭）
- 评测判分逻辑改动（子串匹配口径不动）
- 全量 96 题回放与开启态评测臂的执行时机（代码审查通过后由 Ban 批准）

## 需求

### 功能需求

- **FR-1** 证据装配：校验器输入 = 待校验文本 + 本轮用户问题（适用条件判定的语境）+ 绑定引用片段原文 + 本轮全部片段（按相似度排序、字符封顶进配置面）+ 断言中记录编号对应记录摘录；全部来自本轮已登记证据（既有片段集与事件），不新增检索调用。
- **FR-2** 断言抽取：校验器 LLM 一次调用把文本拆为原子断言清单（每条含断言文本、依据片段引用/记录编号）；不改草稿生成提示词；无断言返回空清单。
- **FR-3** ID 存在性校验：代码级核对断言绑定的引用是否存在于本轮证据集；不存在的引用使该断言直接判"证据不足"（不经语义校验）；此核对同时补上片段引用 ID 真伪缺口。
- **FR-4** 批量语义校验：独立 LLM 调用逐断言判定四档（支持/部分支持/矛盾/证据不足），证据集口径见 FR-1；部分支持必须附越界维度定位（对象/时间/数字/适用条件）与收紧表述建议；缺定位视同证据不足（grill 默认假设，clarify 复核）。
- **FR-5** 处置：支持→放行；部分支持→句级替换为收紧表述（替换句过数字/编号子集校验，越界则降级）；证据不足→降级"未能核实"（复用统一口径，幂等）；矛盾→同样降级"未能核实"，但分歧详情（冲突双方出处与冲突点）落入事件载荷与回放报告——不在回答中呈现分歧（评测口径稳优先）；全量回放若显示矛盾档占比高，另行立项升级为"呈现分歧"。处置零新增模型调用（收紧表述由校验调用一次性给出）。
- **FR-6** fail-open：校验器任一环节失败（模型调用失败、输出解析失败、证据装配异常）时放行原文并记录事件；不阻断回答、不产生 `run.failed`、不改变轮次终态。
- **FR-7** 接线与开关：接线点为 multi-agent 统一作答出口的单点追加；配置面开关默认关；关闭时零行为零事件变化；开启时新增事件类型经既有 JSON 事件通道承载，不改既有事件类型、检查点形状、用量统计口径。
- **FR-8** 旁路回放：从验收臂事件库恢复草稿与证据，重放确定性校验链后执行校验器，产出逐题逐断言判定 JSONL；回放脚本只消费事件与题库，不重跑 agent 循环。
- **FR-9** 断点归类：按题库标准证据映射归类四类断点（表述越界/没召回/绑错/矛盾）并产出汇总报告（分布+逐条样例）；通过题产出误伤基线。
- **FR-10** 冒烟验证：小样本回放（约 12 题：三类断点各抽失败题 + 若干通过题）作为本轮开发验证交付；全量 96 题回放与开启态评测臂另行批准执行。

### 关键实体

- **断言（Assertion）**：原子化事实陈述 + 依据引用（片段 ID/记录编号）+ 绑定状态。
- **断言判定（AssertionVerdict）**：四档判定 + 越界定位 + 收紧表述建议；其结构是能力侧与消费侧的共享契约（先行提交，两树按契约开发）。
- **校验结果（AssertionAudit）**：一次校验的产物——判定清单、处置动作、fail-open 标记；在线事件载荷与回放报告共用同一结构。
- **断点归类（AssertionBreakpoint）**：评测侧四类断点 + 归类依据（期望证据命中状态 × 判定档位）。

- **SC-1** 开关关闭零回归：既有测试全数通过；专项测试以可证伪形态证明开关关闭时行为与事件与 009 一致（零新增调用、零新增事件）。

- **SC-4** 冒烟回放报告：约 12 题产出四档判定与断点归类，三类断点至少各 1 例，通过题误伤样例可查。
